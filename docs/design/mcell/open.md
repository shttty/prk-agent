# 十项决定以外的取舍

以下均为**待确认、按推荐实施**。没有需要改 Pi/OMP 上游的阻塞项。未用现场故障率作概率；能由操作必现的写触发条件，其余注明未测频率。

|项|推荐（已写入设计）|选择依据、代价与备选|
|---|---|---|
|O1 待确认：宽限多长，配置如何生效？|沿用全局 `[kernel].interruptTimeoutMs=10000`，不再让实例覆盖该策略；`interruptRestart="auto"`，可设 never。省略 restart 取配置，显式 auto 即到期升级；首次受理固定策略/截止时间，改配置不影响在途。`maxActiveCells` 在建代时固定。|旧实现已使用 10s。Bun 私有 resolver 在亚毫秒结束，但某些原样 DNS 等待可超 10s，届时会连带丢 namespace；保留这些查询的场合可配更长或用 never。不要把整个 scope 清理用的 closeTimeoutMs 也改成 10s。|
|O2 待确认：never 怎样让模型看到实际卡点？|第一次 never 最多等剩余 N 秒；超期返回 stopping、最后观测的操作/栈/时间、同代 peers 和 now 的后果。后续 read 取快照，无新的轮询协议。重复显式策略可更新至落闸前，但不重新计算 N。|只回 requested 会把原生阻塞与已退出混在一起；另发一套“停止失败”唤醒增加事件种类。冻结的 Bun/GIL 也会冻住诊断采样，此时只能写当前未知，不能声称卡在某一 fd。|
|O3 待确认：整代清理没有回执时如何解除占用？|主动退休确认完成的目标与同伴均 aborted/`kernel 重启`。stop 失败则旧代 fenced，报告清理未确认和具体 scope/PGID，人工检查或下次**明确**恢复时核实旧代已退出再开新代。若连接/Gateway 本身丢失、只有 open 则按 KASYNC 报 unknown，不合成主动退休回执。|Bun 同步子进程样本在只杀父进程后仍有 sleep；unscoped 且子孙脱组时不可能从父进程死亡证明全部清理。此异常路径频率未测。不能把发出 stop 当作物理退出；代价是目标失联时宁可暂时不新开，不增后台扫描器/常驻 reaper。|
|O4 待确认：网页无明确 cell 的总停止按钮？|浮条/ask 一律只停所选 cell；composer 有 operation 就停该轮，并可携显式选中的 cell。多后台 cell 且未选时不暗选第一个；无活动轮时从展开列表选。用户动作触发的整代退休对其连带项一并抑制唤醒。|旧单槽里“所见 cell”唯一，多位时任取列表首项会误停工作，且可能升级杀全代。利用已有行按钮和 cellOnly 字段，不增“全部停止”按钮。|
|O6 待确认：共享状态下怎样展示语言特性？|Python 并发期只列共享变量快照，重叠 cell 只显式收图；不重叠保留自动收图。Bun 持久写 `globalThis.x`，最后值用 `return`/display，JS/TS 均可，TS 只转译。两语言描述各给一行例子。|结束时扫描所有 figures 会关掉同伴未画完的图；两个 cell 同时跑是此问题的触发条件。为任意 JS 顶层声明写跨 cell 变量提升器或做写归因成本高，且不是共享 namespace 的必要条件。|
|O7 待确认：语言由谁切、装包由谁做？|会话详情与独立 model-only `kernel_language` 共用空闲 action，缺省 Python；派生会话新建时继承父语言值，不继承堆，单独会话未选则 Python。npm 走显式实例维护动作：实例 registry/作用域映射 + 指定包版本，目标准备并锁定，下一代选新版本；缺源禁止安装。|不在 `kernel_code` 参数里顺便切语言，避免一次普通求值丢变量。包集按目标建；异架构可安装“成功”而缺 `.node`。保留一次真实导入验证比给运行中 cell 开安装通道简单。|
|O8 待确认：N 路资源预算与旧容量配置？|N 是执行位上限，不保证所有负载都能装进窗口；扣除至少一个 cancel 帧、一块回复的条数/实际字节余量后才接 execute，低容量配置不能表达最小闭环时在准备阶段给配置错误。图片沿用 8 张/20 MiB 每项，并用同一 20 MiB 约束在途代级图数据；原始诊断复用 maxOutputChars。|默认 32 请求/2 MiB 窗口与 4 位兼容，满窗则不再准入。4 项同时交大图会把单 cell 上限乘四；共享在途计数和 omitted 比引入全局资源调度器便宜。不给每个 cell 虚构内存读数。|
|O9 待确认：纯定时等待最多保位多久？|推荐 `maxTimerWaitMs=300000`（5 分钟，可配置），0 禁用延时。仅在原 N 内确认的无 fd 有限等待可一次延到观测上界；超上限按原宽限升级，到获准截止还未退出就升级。never/now 是显式覆盖。|上限太小会为一次已知 sleep 丢整代；太大则四个 sleeping cell 可长期占满。3.9 相对 timeout 可能高估，不把上界当实际退出时间。|
|O10 待确认：isolated 的预载和数据预算？|推荐按代启动一份 forkserver，`forkserverPreload=[]` 默认不预载；每次输入包及返回包各不超过现有 `processWindow.maxBytes`（默认 2 MiB，仅复用数值，不占 Gateway 传输额度）。超限直接报错，不转临时文件、不改 main 绑定。|早启多一个轻量解释器，换取首次 isolated 可立即确定是否可用；预载 NumPy 能共享只读页却有 RSS/线程成本。每 fork 的 Threads 检查不能以 import 成功代替。|
|O11 待确认：isolated 停止的承诺边界怎样呈现？|推荐写清“能 kill 该任务的独立进程组，不影响其他执行位；不是安全沙箱”。若无法确认组退出/EOF，保留清理未确认，告知可显式 now；不把一次 isolated 的收尾失败静默转成整代成功。|任意代码可自行脱组；pickle 的自定义打包/还原也可能执行用户代码。给有风险的耗时任务选隔离，不建议把敌对 pickle 或带有重还原副作用的对象传回主解释器。|
|O12 待确认：首次 pin 前的 socket 身份缺口|推荐实施两次 syscall/集合校验和三处 inode 核对；对已知共享/并发换 fd 场景，工具明示共享连接连带风险；不确定时可选 isolated。不能把它写为对任意并发 close 的原子保证。|首次 syscall 采样与首次 fstat 并不原子；已有三个受控复用点的实测见 `probes/results.md`。若还要求首次取身份之前就必须证明原 fd，现有 `/proc` 接口不提供这个证明，应跳过此分支，而非伪造保证。|
|O13 待确认：请求停 A，阻塞共享 loop 的却是 B，怎样报告？|推荐 `blockedAt` 同列目标 A 和已证实的阻塞者 B；只为 A 投递 task.cancel，不向 B 注入。模型可另选 B 定向停、对 A 选 never，或显式退休同代。无法证明占用者时只报未知。|在同一个 loop 线程上，最后启动的 task 不一定是当前运行者；错停 B 可能使它正在修改的共享对象只更新一半。把已知阻塞者显示给模型比自动取消同伴可审计。|
|O14 待确认：跨 cell 保留的异步连接何时关？|推荐视为该代用户 namespace 的资源，由用户显式 await 关闭；单 cell 的 finally 只清本次操作，代退休时一并清理。用户自己脱离根 task 派生的后台工作不凭线程或最后一个 cell 归属。|创建 aiohttp 会话的 cell 往往先结束；若 cell_end 自动关客户端，下一 cell 即使仍在同一 loop 也不能复用连接。|
