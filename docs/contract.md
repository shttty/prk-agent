# 规则：跨进程与跨机器通信约定
- `GEN-1` Gateway 必须独占会话、kernel 与 SDK 权威状态，SDK 会话由会话运行时创建；Web 与 attach 不得另建宿主、会话存储或调度器。
- `GEN-2` 每条边界必须在入口一次性校验结构、类型与上限，未知字段与不支持的方法必须在调用宿主前拒绝；实例创建与编辑遵循同一未知字段拒绝规则。
- `GEN-3` 传输必须限连接、帧、缓冲及未消费请求数和字节，满时拒绝或有界等；取消非消费确认。PTY daemon无界入队风险已接受，入队非消费；PRK逐终端串行限输入。
- `GEN-7` 路由身份必须来自路径；请求体与查询不得携带未声明的路由参数。
- `GEN-8` Gateway 辅助会话必须使用中立 PRK home，不得把启动目录的项目资源发布到全局清单。
- `GEN-9` 进程内外必须只使用 Pi 原生会话身份；`session_manage` 各 action 均用 `sessionId` 指定管理对象，不得另发会话身份。
- `GEN-10` Gateway 必须仅发布内置、models.json 与按 packages 顺序识别的 provider 所有者模型，手写同名 ID 必须优先且不得合并。
- `GEN-11` 会话provider不得改共享模型；已有所有者无操作确认，其余结构化拒绝。host预检必须独立短命进程，不建会话、运行hooks或双载。
- `GEN-12` Gateway必须独占provider所有权；争用须拒绝，所有者变更提示重启；重启前保留模型与会话，普通CRUD不得改共享模型。
## 客户端 ↔ Gateway
- `WEB-1` wire 请求必须是 UTF-8 换行 JSON 的 v1 信封，同一连接内的请求 id 必须严格递增。
- `WEB-2` 请求 id 只用于关联应答，不得兼作会话、操作、任务或结果的身份。
- `WEB-4` HTTP/WS 转发前必须校验 Host、Origin、Fetch-Metadata、结构与请求体上限；普通请求体限总时长，上传限等字节时长，停滞报 408 并关闭。
- `WEB-5` 每个受管路由必须使用其唯一原生 `sessionId`，不得在原路由替换会话身份。
- `WEB-6` history、historyPage、native、toolContent 必须仅按路径原生 `sessionId` 定位会话，不得接收额外视图参数。
- `WEB-7` 只读不得改运行时、推进 leaf 或接管未受管文件；对话页必须取原生分支而非 SDK 内存，最多 50 用户轮且整轮遵守字节预算。
- `WEB-8` 文件或引用必须校验目标、会话与绝对路径；传输同源 POST、无总量和总时限，上传用原始字节，下载声明附件和 Content-Length，流中失败即中止。
- `WEB-9` 附件的媒体类型与大小上限必须在校验和解码两处保持一致。普通发送可在携带附件时提交空白正文；无正文且无附件必须拒绝。
- `WEB-10` 完整工具内容必须按 `sessionId`、`toolCallId` 返回内容与版本，缺失时不得返回空值。
- `WEB-11` 延迟内容必须在会话、工具身份与版本都匹配后才补全；预览不得当作完整内容。
- `WEB-12` 插件界面更新必须校验会话、客户端与宿主；消息及通知必须按原生条目定位；todo浮窗只认`prk-todolist.todo`。
- `WEB-13` 每个页面同时只能有一个在途渲染，排队的尺寸变化必须合并为最新一次；切换会话时旧客户端必须等在途渲染结束再释放。
- `WEB-15` 提问的回答必须按题序校验且只含文本，含非法字段必须整体拒绝；kernel 发起的提问必须随快照公开 kernel 与 cell 身份。
- `WEB-16` 导出必须只经活动 SDK 会话的公开导出接口生成，没有活动运行时必须返回不可用。
- `WEB-17` 制品写入必须转发至 Gateway；Web 进程不得直接写制品清单。
- `WEB-18` 插件必须只存唯一packages；实例环境用独立接口与集合事件，同实例共享下发及真实字节/速率；同步创建须先校验缓存，不得缺环境先建SDK会话。
- `WEB-19` 所选当前会话的恢复终态集合事件到达后，客户端必须重开会话订阅以取得权威快照，不得只刷新会话列表。
- `WEB-20` 文件请求遇标记 `transient` 的 `BUSY` 时，客户端必须等会话状态事件后重发，不得定时轮询。
- `WEB-21` 网关重启必须由 Web 进程直接调用 systemd，不得经 Gateway 套接字；未配置 unit 名必须拒绝，超时必须报告结果未知且不得重放。
- `WEB-23` Vite 代理仅在 Origin 为 HTTP(S) 且 host（含端口）等于请求 Host 时才可改写 Origin；其他来源必须原样转发，后端跨站校验不得放宽。
- `WEB-24` 会话恢复因目标不可达失败时必须返回 `recovery.code:"TARGET_UNREACHABLE"`；客户端只能按该类型值区分，不得解析错误文案。
- `WEB-25` delegation 原生操作必须只修改所选会话，按 {level} 校验并保存到原生会话状态，设置快照必须返回同名字段。
- `WEB-26` 懒加载设置必须使用独立 lazy 命名空间，并按会话、实例、全局顺序解析；同层单工具值必须优先于插件分组值。
- `WEB-27` 能力目录必须返回懒加载状态、继承默认与可用性；懒加载设置不得要求会话重载或更改工具 exposure。
- `WEB-28` root 与 supervisor 设置必须由 Gateway 持久化唯一原生会话身份；root 必须只接受 local 会话，销毁或归档必须清空且不得自动接任，休眠必须保留。
- `WEB-29` 单个会话不可读不得使工作台整体失败；快照必须报告其文件、位置、原因及可用原生身份，schema 错误必须含字段路径。
- `WEB-30` 不可读会话必须在原列表位置保留警告行，位置未知时单列；点击只能显示原因，不得为其打开聊天或发起唤醒，也不得另加重复的顶部提示。
- `WEB-31` 原生身份缺失时不得伪造 sessionId；坏会话定向操作必须保留原因并拒绝，不得修复或兼容数据。
- `WEB-32` 开关必须只改变下一请求声明与即时权限，不得移除注册、更改 exposure 或要求重载；关闭项须从清单、搜索和描述隐藏。全局 kernel 模式保存不得唤醒会话。
- `WEB-33` Gateway 必须以同一 tool_call 钩子拒绝关闭工具，包括模型、kernel、元工具与远程插件的嵌套调用；拒绝必须保留工具名和原因。
- `WEB-34` 条目与分组的 overridden 必须只表示当前层自身键有值，不得把分组覆盖标为成员覆盖。
- `WEB-35` 嵌套工具界面必须按事件真实工具名渲染 call、result 与 shell，以嵌套 toolCallId 返回；外层 tool_call 不变。
- `WEB-36` tool_call 第一层透传目标必须可由原持久参数与结果重建渲染，键沿用 nestedCalls 的自身 id；不得扩展持久格式或猜测其他嵌套结果。
- `WEB-37` 能力写入必须只接受非空且 ID 唯一的 changes 批次；整批校验后一次保存、一次刷新，任一条目无效时不得写入或部分生效。
- `WEB-38` 批量 lazy 可用性必须按整批最终启用状态校验；插件与沉淀工具组必须共享组默认及层级解析，不得按成员名特判。
- `WEB-39` `/api/derivation` 必须由 Gateway 读写，POST 必须经同源校验；非法配置必须以 400 INVALID_REQUEST 拒绝。
- `WEB-40` 派生配置必须拒绝未知字段及非法 role、模型、思考级别、工具模式、布尔值和能力键值，maxDepth 必须为 1..10 整数。
- `WEB-41` 派生设置必须整份替换，保留 config.toml 其余字段并立即更新运行配置。
- `WEB-42` 派生 GET 必须分开返回配置与内置 defaults；space_status 必须同步公开角色描述、工具模式、隔离及深度默认。
- `WEB-43` 设置类原生操作必须以 completed data 与服务端推送更新，非 completed 回滚乐观字段；不得串行重取快照与目录。
- `WEB-44` model 结果必须同时返回调整后的 thinkingLevel。
- `WEB-45` 会话快照、工作台及原生目录不得发布恒定的会话 capability 字段。
- `WEB-46` 原生name与renameSession必须允许忙时改名并先发session_renamed再返回；SDK改名事件必须携带重读行。
- `WEB-47` 结构化改名参数必须各在 HTTP、socket 入站校验；send 文本必须仅在解析为内建 name 后校验名称。
- `WEB-48` `/new` 必须在源 target/cwd 独立新建；醒着的源须空闲，关闭或休眠的源不得唤醒。Web auto 不得执行 `/new`，plain 必须保留。
- `WEB-49` 客户端启动、选中与重连必须以订阅首帧快照为唯一底稿，不得先 GET 快照或工作台；仅流已结束时才可重开。
- `WEB-50` 订阅在首帧前被拒时 SSE 必须只发一个 `error` 事件（JSON 错误形状）并结束，不得改回 HTTP 错误状态。
- `WEB-51` 集合事件只携变更行或状态；客户端必须按 sessionId 与事件类型更新（含 requiresReload、会话关注状态），不得重取工作台或另开订阅。
- `WEB-52` 角色必须随工作台快照与 session_control_changed 的 details 发布，Web 不得另设角色读取端点。
- `WEB-53` Web 服务必须原样转发，不代浏览器拉页；终端及 yield 活 cell 不得轮询，`activeCells` 按流整体替换。
- `WEB-54` 轻量设置必须以会话快照为客户端唯一来源，乐观写入与回滚不得同时改目录 current 或工作台行。
- `WEB-55` 归档会话的 socket 与 HTTP 成功应答必须一致，不得返回工作台；会话与归档组变化必须经集合事件发布。
- `WEB-56` 项目批量归档必须由 Gateway 合并去重派生计划；执行遇错必须立即停止并返回已归档、未归档清单及原因，不得重试或删除项目文件。
- `WEB-57` 带项目创建及改名必须先校验；创建返回快照前必须保存归属；工作台行的项目创建日期必须取自项目记录。
- `WEB-58` 插件资源与能力目录必须公开provider ID和策略错误；拒绝不得隐藏其他能力；须发布启动warnings/error；包须给版本、来源类型与Gateway home缩写值。
- `WEB-59` 启动识别必须记录 provider 所有权；客户端不得从模型名或插件文案推导所有者。
- `WEB-60` 休眠会话必须允许修改模型、思考档、工具档、委派、本机工具、能力与模型范围；设置不得唤醒会话。
- `WEB-61` 模型回退快照必须公开原模型、默认模型与原因；网页必须显示提示，确认或显式换模型后清除。
- `WEB-62` 被技能／扩展加载策略排除的目录项不得仅因未注册触发 `requiresReload`；新建、唤醒、模型回退同规则。
- `WEB-63` 实例定义、接口、工作台和 `space_status` 必须以 `id` 路由、`label` 显示，拒绝定义 `name`；会话及其余引用仍用 `target`。
- `WEB-64` 手动压缩的控制应答必须只确认接纳及 operationId，不等模型；终态走操作事件，按 ID 停止；可选指令为文本而非轮数。
## Gateway ↔ kernel
- `KER-1` 回调必须沿用 SDK 可调用工具的声明与校验，不得暴露禁用工具；`skill_manage` 须按 action/section 校验平铺参数。
- `KER-2` REPL 必须独占不继承的协议 fd；唯一 reader 不等用户执行；ready 匹配代次、语言并报实值；执行 stdin 必须 EOF，原始输出不入协议或结果。
- `KER-3` 状态与输出须按cell路由；无主诊断仅入本代有界缓冲。同步/异步回调均限本cell活期；ask仅暂停本项硬限及提醒。匹配准入帧前不得yield或写open；准入非消费确认。
- `KER-4` 回调随cell取消且匹配代/cell/request，撤权/ask、丢迟答。取消/回复块同流各留一位等消费；取消不得重投；取消/停用非退出。仅原宽限内确证纯定时等待可限额延时一次。
- `KER-5` 执行必须先占位，建代固定位数；仅Python传默认模式快照及显式模式。满位、维护或窗不足报transient BUSY，不排队或退休；终帧只结算匹配请求。
- `KER-6` 进度只能送往界面，不得进入模型结果；cell内须限额保留后缀并节流合并发布，结束或失效后不得迟发。
- `KER-7` clear/restart/删变量须连接且空闲，库更新互斥，重载换主后更新；reset可退休忙代。切语言必须空闲，先验运行时、确认旧代退出再保存；新代须等清理确认与结果冻结。
- `KER-8` 主动退休必须先封准入与旧帧，再截取已提交未终态项；确认所属 scope/进程组已清才报 `aborted`，否则报 `unknown`；保留已收终帧。
- `KER-9` REPL 意外退出或断链必须作废旧 namespace；未收终帧报 `unknown`，保留已收终帧；不得把断链当退出证明。
- `KER-11` 失效执行不得重放或静默替换；仅下一次明确新请求才可准入新空 REPL。
- `KER-12` 目标连接或 REPL 失效后不得后台创建替代 REPL。
- `KER-13` 文件模块必须经所属 cell 的 executeTool 专用回调返回钩子结果，不得合成事件或向忙碌 kernel 再发 execute；普通回调必须遵守开关。
- `KER-14` 文件回调请求必须限制为 1 MiB UTF-8 JSON，结果必须限制为 256 KiB；超限与失败不得重放。
- `KER-15` PRK 文件模式的远程嵌套 read 必须只携带展示页参数，不得经 Gateway 读取或转发该页正文；插件追加结果必须交还 kernel。
- `KER-16` 远程写入钩子完成后 kernel 必须在目标机重读并核对写后 SHA-256，由同一文件会话刷新实际修改区段引用，不得复用写前引用。
- `KER-17` Python files模块必须常驻；原生工具开关只切声明与权限，不得重启kernel、移除模块或清空变量；原生开启时须在文件IO前拒绝PRK文件函数。
- `KER-18` 子会话结果与未交结果的操作异常终态必须通知当前 owner；同一失败至多一次，不重放，不提供 gateway.wait 或轮询。
- `KER-19` Python不得落盘；forkserver同scope独立exec、逐fork验单线程；pickle各限maxBytes、不出代。按代/cell停已握手组；子进程回收排空才结算。
- `KER-20` code 回调必须优先传 structuredContent，否则传文本，不得猜测 JSON；PRK 结构结果必须声明 outputSchema，失败在所属语言抛异常。
- `KER-21` kernel 函数每次调用必须经所属 SDK cell 的 typed permission 回调校验权限；严格字段及名称、限4KiB，取消后不回复。
- `KER-22` result:file 的 PRK 出口必须绑定所属 kernel 的瞬态调用上下文，不得让普通 gateway、元工具或插件调用借同名原生工具绕过关闭权限。
- `KER-23` PRK read 与 cell 图片必须限张数，同代共用原始字节额度（含未完成块），超限排水并省略，冻结后释放；保留图经 Gateway 压缩为 ImageContent。
## Gateway ↔ 目标机
- `TGT-1` 新增完整实例必须触发下发；必须在目标以shell校验SHA-256并发布，取消/关闭必须清理所属上传及解压暂存，不得扫描恢复。
- `TGT-2` 下发须含所选runtime、SDK、host插件、声明二进制及所需托管Python；创建/唤醒/重载只读缓存，缺失须拒绝，不得隐式下载。
- `TGT-3` 不支持的平台、缺失或不可执行的制品必须拒绝；托管Python下发前必须比对目标glibc与制品实测最低版本，不得改在Gateway执行。
- `TGT-4` 制品上传必须在 HTTP 入口校验身份、平台、哈希、内容类型与大小上限；不得设总时限。
- `TGT-5` 制品上传失败必须清暂存且不得发布；Bun包集只在目标维护期按锁准备、真实导入后发布，运行期不得装包或回退公网。
- `TGT-6` 文件必须走所属目标；列表限额明示截断，预览/在途限额；传输按块背压，上传限等块确认、同目录暂存并原子改名，失败清暂存；断链未确认报 UNKNOWN 并记录暂存路径。
- `TGT-7` cwd 不存在或不可访问必须失败，不得换目录补救；目录删除必须拒绝非空目录。
- `TGT-8` 保存时 `expectedLastModified` 不匹配必须返回 `CONFLICT` 且不写入。
- `TGT-9` 文件冲突后客户端必须重读再决定是否覆盖；时间戳检查不得宣称为原子比较交换。
- `TGT-10` 同一会话的同名终端必须共享在途创建、计入配额，并只维护一个 owned PTY。
- `TGT-11` 终端 WebSocket 必须使用独立的 Gateway 连接和有界、有序的发送队列。
- `TGT-12` 终端不得缓存、排队或重发未送达与被拒绝的输入。
- `TGT-13` 终端只能对标记 `transient` 的 `BUSY` 建连错误做有界退避，关闭码 4000 之后不得重连。
- `TGT-14` 网页中断必须匹配模型命令与PTY代次；网页、硬超时或输出刹车中断无效须确认关闭后重建；人工终端保留名及owner，在结果和通知说明。yield仅限前台等待。
- `TGT-15` 后台完成、cell 台阶、终端退出/已开启静默及 warning 必须走 SDK 原生消息；终端 warning 不得被前台等待或静默开关抑制。
- `TGT-16` 终端 quiet 不得当作在等待输入。
- `TGT-17` 同一实例的远程扩展必须复用 Gateway 共享目标通道，不得按会话或插件另开控制连接。
- `TGT-18` 帧与回调必须绑定目标代次；帧限16MiB，双向分块限窗口并等消费；忙时拒新请求，已接纳reply/abort须等单帧完成，不得交错、另排队或重放。
- `TGT-19` SDK/宿主必须独立制品；插件仅含自身与锁定依赖，本机直链、远端按当前hash。解析/打包失败仅该包不可用，不得退旧包；传输/校验失败须整环境失败。
- `TGT-20` PRK 文件出口必须只使用所属实例的共享目标通道，不得在 Gateway 执行目标路径的文件操作。
- `TGT-21` PRK 文件 edit 必须在目标机一次请求内完成匹配与原子替换，只返回有界差异、路径和写后哈希，不得往返整文件。
- `TGT-22` PRK 文件出口两端必须执行同一预算：请求 1 MiB、结果 256 KiB、read 2000 行/50 KiB、edit/write 文件 200 MiB。
- `TGT-23` 远程原生七工具必须经既有扩展桩转发至目标宿主；所有调用来源必须执行同一 Pi 定义，read 必须返回原生正文或图片。
- `TGT-24` 原生宿主必须离线使用下发的rg/fd；托管Python必须由uv用本地镜像离线安装；未配置PyPI镜像时uv不得联网。
- `TGT-25` 原生工具与 PRK 文件出口必须互斥；无插件时必须在首次原生执行才启动宿主，仅加载已复核且与项目精确固定 Pi 版本一致的工具／总线模块，其他版本必须拒绝，不得执行或回退包根。
- `TGT-26` 原生工具声明必须标明 Pi 身份；Gateway 必须从同版公开定义恢复参数准备与渲染，执行必须原样转发至目标宿主。
- `TGT-27` 每会话每目标机必须只运行一个远程宿主，原生工具与全部目标插件必须共享 Pi 原装事件总线。
- `TGT-28` 每宿主必须由短命Python根fork执行；Linux根须设父死信号；优先独立systemd scope限内存，不可用须记日志并回退独立进程组。
- `TGT-29` 宿主内存遥测必须只读自身 scope 上报，无 scope 时必须标记 `scoped:false` 且不得伪造内存上限或 OOM 计数。
- `TGT-30` 宿主启动请求必须携带 runtime 绝对路径与 runtimeArgs 字符串数组，目标机必须按 argv 原样传入所选运行时，空数组不得补默认值。
- `TGT-31` 目标通道必须在XDG_RUNTIME_DIR或/tmp的短mkdtemp目录监听一次Unix socket；握手须校验宿主pid、rootPid及亲子/组归属，不继承fd。
- `TGT-32` accept 后必须 unlink 并关闭 listener，退出或启动失败必须 rmtree；不得增加权限、属主或残留扫描检查，启动期限不变。
- `TGT-33` 目标失败或期限退休必须报 `TARGET_UNREACHABLE` 并拒绝等待、作废本代；旧租约不得影响新代，不得后台重连或重放。
- `TGT-34` 远程项目资源必须仅按会话 cwd 在目标机发现，不得读取 Gateway 的同名项目路径。
- `TGT-35` 资源发现必须批量返回有界上下文、设置、提示模板与技能元数据，超限必须明确失败，并沿用所选宿主运行时。
- `TGT-36` 项目扩展必须由会话远程宿主直接加载目标路径，不得打包或回传扩展正文。
- `TGT-37` 资源发现必须保留通道错误类型，仅资源校验失败可映射为请求校验错误。
- `TGT-38` 技能与提示模板必须以目标项目覆盖 Gateway 全局，不得发布目标用户级资源；沿用 Pi 各自查找规则，同路径技能按来源优先级去重。
- `TGT-39` 本机目标发现与 Gateway home 相同的技能目录时，必须仅由 Gateway 全局来源发布一次。
- `TGT-40` 目标源码必须经 process stdin 内存执行；Python 跨 scope 不得经 argv 交接。READY 绑定本代；启动、分帧与窗口同预算，应答处理后确认消费。
- `TGT-41` 注册版本必须只在创建或显式目录查询时经已有通道读取；最多4096项，请求与结果各限256KiB；不得回传正文或启动kernel／宿主。
- `TGT-42` 隔离仓库发现、detached worktree 创建、patch 生成与清理必须在所属目标机执行，不得操作 Gateway 同名远程路径。
- `TGT-43` Gateway 发布 patch 必须沿用既有通道；patch 最多 16 MiB，原始分块最多 192 KiB，stats 最多 64 KiB。
- `TGT-44` patch 必须用临时 git index 对 baseCommit 合成已提交、未提交及未跟踪文件，不得改变工作树自身 index。
- `TGT-45` 仅非空 patch 必须写制品并返回 path/bytes/stats，目标机必须能写同一绝对路径供父会话显式 git apply。
- `TGT-46` 隔离交付前必须校验父 checkout 的 HEAD、tracked 及 untracked 内容；任何变化（含父会话并发修改）必须拒绝结果。
- `TGT-47` 隔离工具进程必须设置 GIT_CEILING_DIRECTORIES，子会话提示词必须禁止改动父 checkout。
- `TGT-48` `terminal_textsend` 必须拒绝非 `\t`/`\n` 控制字符与 DEL，按实时 `?2004` 或提示符 base64 送达全文并保留原 `command`。
- `TGT-49` 人工终端必须经公开 PTY argv/env 启动 /bin/bash 并在登录环境后安装标记；不得落盘或经 PTY 键入 rc。
- `TGT-50` 人工终端无就绪标记时，列表与工具结果必须标注命令级跟踪不可用，硬超时输入必须在执行前拒绝。
- `TGT-51` 正常关闭或重启人工终端必须由用户明确要求；工具必须声明此规则，不得检测用户意图；硬超时重建除外。
- `TGT-52` prk_ssh 必须用 --rcfile 在内存加载发起端 base64 rc 并支持多跳；已开始命令收到 B 必须以 null 退出码结束，不得改普通 ssh。
- `TGT-53` PTY必须设TERM=xterm-256color、COLORTERM=truecolor、TERM_PROGRAM=prk并清继承标识；人工、模型与prk_ssh须保留真彩色。
- `TGT-54` 浏览器与 Gateway 终端接收 `CSI 2 J` 必须把当前屏推进滚动缓冲，接收 `CSI 3 J` 不得清除滚动缓冲。
- `TGT-55` 模型命令超限必须按 output_brake 仅发一次 Ctrl-C 或 warning；status 必须据实结算，人工输入不得刹车或通知。
- `TGT-56` 超限命令必须仅保留有界 UTF-8 头尾与丢弃字节标记，中段不得取回；分页与 total_bytes 必须对应保留文本。
- `TGT-57` 用户连接原文仅由本机 `/bin/sh -c` 执行，不得附参；探测/部署/exec 仅走stdin；pi-env hello 必须为 1.6.0/v1 且声明 process。
- `TGT-58` 终端宿主变尺寸或重新可见时必须按实际组内尺寸fit，并向同代PTY发送cols/rows。
- `TGT-59` 同代终端的HTTP关闭回执与WS终态必须幂等移除视图；旧代终态不得关闭新代视图。
- `TGT-60` 连接/部署/超时错误必须保留TARGET_UNREACHABLE及details.reason=connection/deployment/timeout。
## 请求、结果与事件顺序
- `REQ-1` send 与 cancel 的接受应答只表示请求已收下，不得当作操作终态。
- `REQ-2` 操作终态必须等已接受的 SDK 调用完成且 SDK 空闲，中间的重试错误不得当作终态。
- `REQ-3` 用户显式取消必须结算为不带 error 的 `cancelled`。
- `REQ-4` 停轮按操作ID，否则按所选cell；匹配代次和ID、不得代选同伴。cellOnly不停轮、不清队列；定向只撤本项ask与未发提醒，不取消同伴；退休撤全代。停止及落账不唤醒。
- `REQ-5` 客户端观察传输被拒或断开不得取消已接受工作；所属目标控制连接断开必须退休代次且不重放。
- `REQ-6` 超时或断线后未确认的请求必须标为 `unknown`，不得推断远端没有副作用。
- `REQ-7` 未确认请求的后续处理必须以重连后的权威快照为准。
- `REQ-8` 输入、模型请求、`kernel_code` 执行，以及 send、cancel、closeSession、shutdown 都不得自动重放。
- `REQ-9` `failed` 与 `unknown` 必须保留为操作结果，SDK 空闲后会话必须回到 idle。
- `REQ-10` 需醒态的命令必须与普通输入共用唤醒准入，再按实态执行；启动失败必须以 `submitted:false` 拒绝并给原因，保留会话可读。 `reload` 不得唤醒或创建运行时。
- `REQ-11` shutdown 应答不得代替对进程退出与端点移除的观察。
- `REQ-12` 进度与流式增量不得累加成最终结果；思考增量必须带 `details.part:"thinking"` 发布，客户端不得并入正文。
- `REQ-13` 观察不得唤醒、分配 kernel、启动采集或调用模型。休眠输入框聚焦或输入须发 wake，在途或已确认不得重复，失败须可见。
- `REQ-14` 换target/cwd必须用`recoverSession:new`并给target；Python REPL与模型终端共用实例Python≥3.9或托管venv。
- `REQ-15` `recoverSession`的`auto`不得更换target/cwd；待补配置执行必须以submitted:false及configurationIssue拒绝。
- `REQ-16` 远程扩展调用、事件与反向回调不得在超时、断线或进程退出后自动重放。
- `REQ-17` 工具/命令/事件不得设固定期限；必须在原宿主执行handler并回传上下文/结果，UI沿原通道；同步能力按包结构化拒绝，不得双载、绕schema或重放。
- `REQ-18` 停止及宿主释放必须立即作废在途钩子并发送 abort；迟到结果不得改变已结束调用，handler 错误必须沿用 Pi 语义。
- `REQ-19` session_spawn 的 cwd 必须在新建会话前按同一绝对路径规则校验，显式值必须传给所选目标。
- `REQ-20` session_spawn 必须接收 tasks[] 与共享 context，逐项返回准入结果；部分失败不得重放已接受的子任务。
- `REQ-21` outputSchema 必须随子任务保存，session_result 必须先校验结构化 output，失败不得提交或发布成功结果。
- `REQ-22` 会话工具必须只发布 session_spawn/send/result/list/manage，不得保留旧工具别名。
- `REQ-23` 同伴消息必须非阻塞入箱；steer 必须在 turn_end 投递，followUp 必须经 SDK 整轮边界投递。
- `REQ-24` abort 消息必须先校验控制权，再中断当前操作并合并积压开启新轮；kernel 与变量必须保留。
- `REQ-25` 结果必须先写父会话原生 receipt 并标为 delivered，再入其收件箱；不得要求确认或重放。
- `REQ-26` 转交提议必须入接收方收件箱；显式 accept 前不得换 owner，接受后不得改 createdBy。
- `REQ-27` abort 与管理操作必须只允许祖先、root、同项目 supervisor；定向 accept 与用户操作除外。
- `REQ-28` session_spawn 的 lifecycle 必须只接受 temporary／persistent；user 必须仅由用户升级产生。
- `REQ-29` 内部插件组开关必须同步控制声明、所属主题节和 tool_call／gateway.* 权限；懒加载只隐藏声明，不得重建 SDK／kernel 或改变调用能力。
- `REQ-30` session_spawn.tasks[].label 必须为非空字符串，不得接收 toolMode；工具档位必须按 role、派生全局、宿主默认选择。
- `REQ-31` role capabilities 必须与 toolMode 写入同一条初始原生会话状态；模型与思考级别必须按请求、role、父会话选择。
- `REQ-32` 派生必须按 owner 链计算深度（顶层 0），超过 maxDepth 必须在创建子会话前拒绝。
- `REQ-33` 子会话 instructions 必须按 role 显式值、全局值、内置文案选择；空串不得注入 Role instructions。
- `REQ-34` isolated 必须按请求、role、派生全局、false 选择；非 git 仓库必须拒绝隔离并提示可关闭隔离。
- `REQ-35` 隔离必须从目标仓库 HEAD 创建 detached worktree，保留 cwd 仓库内相对路径；不得留下子会话分支。
- `REQ-36` 隔离元数据必须平铺记录 isolated/repoRoot/worktreeRoot/baseCommit；session_result 必须先生成 patch。
- `REQ-37` 非空 patch 必须附于 result 和父收件箱，字段为 path/bytes/stats；绝对路径必须去重加入 artifacts，空改动不得产物。
- `REQ-39` `session_list` 精简列表必须包含调用者，仅其有 `self:true`；与 `space_status` 一样只发布为真的 `root`/`supervisor`。
- `REQ-40` 定向 session_list 必须只允许自身、owner 链祖先、同项目 supervisor 或 root 读取目标。
- `REQ-41` 定向 session_list 必须读取最新权威消息与执行中输出，并限制最近条数与单条文本长度。
- `REQ-42` 派生配置与目录必须保留可覆盖的 task/small 内置角色；session_spawn 省略 role 时必须选 task。
- `REQ-43` 模型终端输入工具必须只发布 `terminal_textsend` 与 `terminal_keysend`，不得保留旧工具别名；开关必须用 `terminal_set`。
- `REQ-44` `memory` 与 `memoryChange` 必须接收非空 `operations`；按 action 整批校验字段，任一项非法不得写入。
- `ORD-1` 必须仅在计数器不会重来的同一身份内比较序号与修订号。
- `ORD-2` 必须在计数器可能重新开始时同时改变其所属身份。
- `ORD-3` 必须在客户端遇到身份变化时整体丢弃旧身份状态，并以新身份快照为底重新接收增量。
- `ORD-4` 必须对快照与增量执行相同的身份与顺序规则，不得以权威快照或重连为由跨身份比较或合并旧状态。
- `ORD-5` 订阅必须先装监听再返回快照，之后的增量以该快照为基线。
- `ORD-6` 传输事件不得持久化或重放，重连须取新快照。后台 cell 必须逐项先落账再通知；未发提醒须核验本项仍运行，终态通知须核验所属分支回执，送达只认同分支原生消息。
- `ORD-7` 迟到的渲染结果不得覆盖较新的标量、编辑器状态或其他会话的组件。
- `ORD-8` 插件对话框的出现与关闭必须直接反映在标量快照里；等待、重试宽限与出错停止必须单独发布，不得覆盖生命周期状态。
- `ORD-9` 会话快照、事件与 `messages` 结果必须携带 `streamId`，`sequence` 仅在同流内比较。
- `ORD-10` `streamId` 必须由进程启动 UUID 与宿主实例 UUID 组成；重建宿主或网关重启不得复用。
- `ORD-11` 休眠与关闭会话的零序号必须使用独立稳定的流身份，进入活动宿主时不得沿用。
- `ORD-12` 界面与渲染的 `revision` 必须归属宿主流；同流较旧值不得覆盖已接收界面。
- `ORD-13` `editor.revision` 必须归属同一宿主流；保留宿主的界面 reset 不得重置界面或编辑器修订号。
- `ORD-14` 客户端必须拒绝同流重复或回退的事件序号；完整快照的 `sequence` 不得低于已接收事件。
- `ORD-15` `extension-ui` 结果必须携带 `data.streamId`；异流响应不得改写当前标量、编辑器或渲染组件。
- `ORD-16` 接收新流快照时必须整体替换旧会话瞬态状态及渲染请求关联，不得清除该会话的用户草稿。
- `ORD-17` 对话框 `id` 必须为全局唯一 UUID，旧宿主答案不得命中新宿主对话框。
- `ORD-18` 界面修订身份必须使用宿主 `streamId`，不得另发界面 `generation` 或按两套身份判序。
- `ORD-19` 接收端渲染请求序号必须绑定会话选择、`streamId` 与客户端，退休请求不得覆盖当前响应。
- `ORD-20` 宿主内存与 OOM 计数必须归属同一远程代次；换代必须替换样本，不得跨代累加或用旧样本覆盖新代次。
- `ORD-21` 工作台行 startedAt 必须为 epoch 毫秒；普通会话来自本次运行准入，子任务与结果必须保留任务开始时间。
- `ORD-22` 子会话行及结果的 finishedAt 必须为交付或结束的 epoch 毫秒；未结束必须省略，归档不得改写交付时间。
- `ORD-23` 终态、tree、reload 后必须推一次带分支锚点的轻快照，无消息页或图像；换代用新流。运行态随流不等分支页，持久 entryId 以该页为准。
## 断线、重启与换代
- `LIFE-1` 浏览器断开、关页或只重启 Web 服务不得结束 Gateway 拥有的会话与 kernel，也不得停止 Gateway。
- `LIFE-2` 观察连接断开不得关闭资源；每个会话、集合与终端的订阅必须各自替换与取消。
- `LIFE-3` Gateway正常关闭必须先结算后台cell，将醒着的会话记为休眠，再关闭自有REPL、PTY、宿主及daemon，不得影响无关进程。
- `LIFE-4` 唤醒必须沿用同一会话身份及保存的target/cwd和kernel语言；下一次执行用新空REPL。
- `LIFE-5` Gateway异常退出后旧执行handle必须失效；后台cell须从SDK分支对账，不得认领旧namespace、重跑或补发唤醒。
- `LIFE-7` 会话或 kernel 失效后必须只在明确新请求准入时建空 REPL；观察不得建 REPL，不接回旧 kernel，不重放。
- `LIFE-9` 只重建 kernel 时必须保留会话身份、会话记录与保存的执行选择。
- `LIFE-10` 同代共用一次清理，结算后只释放一次租约；未确认报 `closed:true`、`cleanup:unconfirmed` 及所属身份；旧代未证实退出不得启新代。
- `LIFE-11` 浏览器断开或会话休眠必须保留仍属活 Gateway 与目标连接的终端；观察重订阅不得创建替代 PTY。
- `LIFE-12` Gateway 停止必须关闭人工及模型终端；目标连接失效必须退休旧代次，不得接回或补发输入。
- `LIFE-13` 显式关闭、会话结束或shell自然退出必须结束终端及未主动脱离job；nohup/disown/setsid/tmux等脱离进程保留。
- `LIFE-16` 终端关闭须确认shell退出；close/aborted非清理证明，不得宣称清理脱离进程；非Linux须标注断链清理降级。
- `LIFE-17` 插件界面宿主换代时必须结束待答对话框、清除插件通知，并在重载前重置界面。
- `LIFE-18` 界面关联/下发任务必须只存Gateway内存；按实例streamId/revision判序并沿用集合通道；失联/重启须失效待显式重试，不得续传或重放。
- `LIFE-19` 远程扩展通道断开或宿主退出时必须拒绝待处理调用、取消反向回调，并停用该传输代次。
- `LIFE-20` 远程扩展宿主替换必须重建所属会话宿主，并使用新宿主的 `streamId`。
- `LIFE-21` 释放远程扩展必须只关闭其拥有的子进程与消费者租约，不得关闭其他会话或插件仍持租约的共享通道。
- `LIFE-22` 远程宿主尚未启动时，失败清理必须只释放租约，不得向目标发送停止未登记进程代次的请求。
- `LIFE-23` 网关重启后浏览器必须沿用既有断线重连与新流身份规则，不得另建重启专用的重连机制。
- `LIFE-24` 宿主根必须在父死、宿主退出或关闭时停止所属scope或进程组，覆盖Pi同步卡死；非Linux须声明不保证断链清理。
- `LIFE-25` 远程 abort 回执逾期必须停止所属 scope 或进程组并重建该会话宿主；会话记录与 kernel 必须保留，在途调用不得重放。
- `LIFE-26` temporary 子会话交付后必须等当前 SDK 运行结束再停止归档；项目首个会话必须成为 supervisor，supervisor 离开项目后必须由最早存活成员接任。
- `LIFE-27` 隔离 worktree 必须跟随子会话生命周期：persistent 后续 steer 与用户 upgrade 必须保留工作树。
- `LIFE-28` 隔离子会话归档或 destroy 必须在目标机删除 worktree；用户升级后必须保留；清理失败只记日志，不得阻塞归档。
- `LIFE-29` 休眠设置必须经原生管理器追加同形条目，与唤醒、休眠及关闭串行交接唯一写入方。交接须等全表各项落账，不等送达；有未结算项不得自动休眠。
- `LIFE-30` 保存模型不可用时必须显式回退到可用的 PRK 默认模型，追加原生模型条目并记录含两模型的日志。
